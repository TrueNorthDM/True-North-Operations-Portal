Decisions

Each one changes the work that follows. The open ones have a recommendation.

1How to leave Supabase Open

Supabase is two things for the portal: a PostgreSQL database, and a layer on top that handles login, every read and write from the screens (563 calls in 99 files), the 111 security rules and file uploads. The two can be separated.

  • The database moves to ScalaHosting's own PostgreSQL service, managed from SPanel with ScalaHosting's backups.
  • The layer on top is open source. The same software runs on the VPS, connected to that database, so the portal works as it does today with no Supabase account behind it.

Replacing the layer instead means rewriting those 563 calls and moving the 111 rules into code: weeks of work and retesting, not days. That path is compared under "If the server can't run it" below.

RecommendedScalaHosting PostgreSQL for the data, open-source Supabase services on the VPS for login, data access and files.

2What ScalaHosting must confirm, and the server size Open

SPanel runs Node.js apps and PostgreSQL, and the VPS comes with full root access. The Supabase services run in Docker and need PostgreSQL 15 or newer, permission to create roles, and the pgcrypto and uuid-ossp extensions. They use about 2 GB of RAM, and the portal with its PDF exports about 2 GB more.

RecommendedAsk ScalaHosting whether Docker is allowed on this SPanel VPS, which PostgreSQL version SPanel installs, and whether we have superuser on it. Size the VPS at 4 vCPU and 8 GB RAM at least. If any answer is no, take the Firebase path.

3A more robust login, by invitation Decided

Today anyone with a company email can sign in, and the only way in is a magic link. The link fails in three common ways: the email is slow or lands in spam, the link is opened on a different device from the one that asked for it, or an email scanner opens it first and uses it up.

  • Invitation only, not by domain. The portal is open to the people an admin invites, whatever their email, and to nobody else. At launch every active person in the Directory is invited: 31 today, of whom 27 have a work email, 3 only a personal one and 1 none yet.
  • Sign in with Google. True North is on Google Workspace, and Gmail works too. It asks only for name and email, so no Workspace admin has to approve anything.
  • A 6‑digit code in the same email, typed on any device, for anyone without Google. The link keeps working.
  • Two-step sign-in (2FA) for everyone. After signing in, a 6‑digit code from an authenticator app on the phone (Google Authenticator, Microsoft Authenticator, 1Password), set up once with a QR code. It is built into the Supabase login, so every page can require it. An admin can reset it for someone who loses their phone.
  • Reliable sending from portal@truenorthportal.online, and longer sessions.

AgreedInvitation only, Google sign-in, 6‑digit code alongside the link, and two-step sign-in for everyone. No domain restriction and no approval needed from IT. It ships on the current portal, before the move.

4The addresses on truenorthportal.online Open

The domain carries the portal's own name, so the portal can live at its root. The data service needs an address of its own, and a test address is used before the move.

Recommendedtruenorthportal.online for the portal (with www redirecting to it), db.truenorthportal.online for the data service, staging.truenorthportal.online for testing.

5Who sends the login emails Open

Today Supabase sends them. After the move the server needs a real mail account, or nobody can sign in with the code or the link.

RecommendedA mailbox portal@truenorthportal.online created in SPanel, with its SPF, DKIM and DMARC records added in Cloudflare so the emails don't land in spam.

6The GitHub account that receives the code Open

A personal account or an organization. An organization is better for a company: people come and go without anyone sharing a login.

RecommendedA True North organization on GitHub, with you as owner.

Questions

Do I need to do anything now?

No. When the new sign-in is ready you will get an email invitation; accept it, and that's all. We'll tell the team before the portal goes offline.

Will anything be lost?

No. All the data (time entries, reports, the Directory, My Work) is copied to the new server and checked against the old one, number by number, before the new portal opens. The whole copy is rehearsed first.

Why is the portal moving?

So that True North owns every part of it: the code, the server, the database and the address. Today they live on services under other accounts.

What if I can't sign in after the move?

Try "Sign in with Google" or the 6‑digit code first. If neither works, let Arnaldo know and he will check your invitation.

What is the second step, and what if I lose my phone?

After you sign in, the portal asks for a 6‑digit code from an authenticator app on your phone, such as Google Authenticator. You set it up once by scanning a QR code. If you lose or change your phone, Arnaldo resets it and you set it up again.

Will the old address keep working?

Until the move, yes. After it, use truenorthportal.online and update your bookmark.
